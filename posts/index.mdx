<Code>
```sh title="" caption="Spawn, move and remove" showLineNumbers
# spawn npc rob at click
spawn npcKey:rob at:$( click 1 )
# must be navigable or actable

# move rob to click
move npcKey:rob to:$( click 1 )
# must be on nav mesh
# must have access to doors

# respawn with skeleton key
spawn npcKey:rob at:$( click 1 ) grant:.

# move via a waypoint
move npcKey:rob to:$( click 2 )

# dust to dust
w npc.remove rob
```
</Code>

Having seen the system in action,
we now list our underlying motivations.

- _Create a video game whose NPCs behave just like human-controlled characters._
  This is related to Turing's Imitation Game:
  The Player interrogates, the questions are video game actions. Can the NPCs fool the Player?

- _As above but with a human Game Master._ Allowing another human to control the NPCs makes the problem more tractable. It also motivates realtime control systems for NPCs.

- _Provide an in-depth explanation of [Recast-Detour](https://github.com/recastnavigation/recastnavigation)._ Our NPCs are controlled by Recast-Detour running as WASM in a web worker. We'll analyse the underlying C++ driving our fabrications.

- _Provide a generic scripting system for [three.js](https://www.npmjs.com/package/three)._ Our xterm.js terminals interpret [mvdan-sh](https://github.com/mvdan/sh) syntax trees as JavaScript. In production one run commands. In development shell functions and processes are synced with JS modules.<SideNote>Technically this approach is independent of three.js.</SideNote>
