<Code>
```sh title="" caption="Spawn, move and remove" showLineNumbers
# spawn npc rob at click
spawn npcKey:rob at:$( click 1 )
# must be navigable or actable

# move rob to click
move npcKey:rob to:$( click 1 )
# must be on nav mesh
# must have access to doors

# respawn with skeleton key
spawn npcKey:rob at:$( click 1 ) grant:.

# move via a waypoint
move npcKey:rob to:$( click 2 )

# dust to dust
w npc.remove rob
```
</Code>

Having seen the system in action,
it is worth listing our underlying motivations.

- __Create a video game whose NPCs behave just like human-controlled characters.__
  Think of Turing's Imitation Game:
  the Player interrogates and the questions are video game actions... can the NPCs fool the Player?

- ___As above but with a human Game Master.___ With another human controlling the NPCs the problem becomes more tractable. It also motivates NPC realtime control systems.

- ___Provide an in-depth explanation of [Recast-Detour](https://github.com/recastnavigation/recastnavigation).___ Our NPCs are controlled by Recast-Detour running as WASM in a web worker, so we'll analyse the C++ driving our fabrications.

- ___Provide a generic scripting system for [three.js](https://www.npmjs.com/package/three).___ Our [xterm.js](https://github.com/xtermjs/xterm.js/) terminals interpret [mvdan-sh](https://github.com/mvdan/sh) syntax trees as JavaScript. In production one can run commands. In development shell functions and processes are synced with JS modules.<SideNote>Technically this approach is independent of three.js.</SideNote>
